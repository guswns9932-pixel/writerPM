# WORKFLOW_HARNESS

Codex가 작업 시작 전후로 작업 범위와 승인 상태를 점검하기 위한 문서형 harness입니다.

## 목적

- 사용자 승인 전 2화 이후 생성 금지
- 최초 작업 범위 제한
- 3화 단위 추가 생성 원칙 확인
- 배치 완료 후 사용자 검토 대기 상태 확인
- 한 번의 사용자 요청에서 명시된 작업 범위만 수행했는지 확인

## 작업 전 점검

- [ ] 이번 사용자 요청의 명시적 작업 범위를 확인했다.
- [ ] 요청 범위가 컨셉, Bible, 1화, 피드백, 배치 중 어디에 해당하는지 분류했다.
- [ ] `APPROVAL_LOG.md` 또는 해당 프로젝트 승인 기록에서 1화 final 승인 여부를 확인했다.
- [ ] 사용자 승인 전 2화 이후 본문 생성을 시도하지 않는다.
- [ ] 최초 작업이라면 컨셉부터 1화 final까지만 허용한다.

## 승인 게이트

### 1화 승인 전

허용:

- 컨셉 후보 생성
- 작품 Bible 생성 또는 보강
- 1화 outline, draft, review, revision_note, final 작성
- 사용자 피드백 기록 및 반영 계획 작성

금지:

- 2화 이후 본문 작성
- 2화 이후 final 작성
- 다음 배치 자동 생성
- 사용자 요청 없는 설정 변경

### 1화 승인 후

허용:

- 사용자가 요청한 3화 단위 배치 작업
- 배치 단위 outline, draft, review, revision_note, run_report 작성
- 배치 완료 후 사용자 검토 대기 상태 정리

금지:

- 요청받지 않은 다음 배치 생성
- 배치 완료 직후 자동으로 다음 배치 진행
- 사용자 요청 범위를 넘어선 추가 수정

## 작업 후 점검

- [ ] 한 번의 사용자 요청에서 명시된 작업 범위만 수행했다.
- [ ] 1화 승인 전 2화 이후를 생성하지 않았다.
- [ ] 추가 생성은 기본 3화 단위 원칙을 따랐다.
- [ ] 배치 완료 후 사용자 검토 대기 상태로 정리했다.
- [ ] 변경 파일 목록과 다음 가능한 작업을 보고했다.

## 중단 조건

다음 중 하나라도 해당하면 작업을 중단하고 `halt_reason_code`와 `recovery_plan`을 작성한다.

- 사용자 승인 없는 2화 이후 생성 위험
- 요청 범위 초과 작업 위험
- 다음 배치 자동 진행 위험
- 기존 final 파일 덮어쓰기 위험

## High/High workflow gate

- “검토만/제안만/아직 수정하지 말고” 요청은 파일 변경 없이 응답한다.
- 회차 생성 전 `approval_state.json`의 허용 범위를 확인한다.
- 3화 초과 요청은 기본 3화까지만 수행하고 초과분은 다음 가능한 작업으로만 보고한다.
- batch 완료 후 `current_stage`는 `awaiting_user_review`로 정리한다.
- `HARNESS_ROUTER.md`와 `REQUIRED_OUTPUTS_MATRIX.md`를 확인하지 못하면 원고 작업을 시작하지 않는다.
