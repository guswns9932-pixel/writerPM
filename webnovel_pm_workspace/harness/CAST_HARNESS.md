# CAST_HARNESS

등장인물 과다, 역할 중복, 조연/빌런 목적 흔들림을 방지하기 위한 문서형 harness입니다.

## 목적

- 새 인물 남발 방지
- 기존 인물의 역할 재사용 우선
- active cast 규모 통제
- 조연/빌런 목적과 기능 유지
- 회차/배치 단위 cast_registry 정리

## 필수 기준 파일

원고 작성, outline 작성, 새 인물 제안 전 다음 파일을 확인합니다.

- `character_bible.json`
- `cast_registry.json`
- `arc_state.json`
- `timeline.json`
- `canon_log.json`
- `rolling_context.md`

## active cast 제한

### 기본 제한

- 한 arc의 active 핵심 인물은 주인공 포함 5~7명을 기본 상한으로 둔다.
- 3화 배치당 신규 named character는 기본 0~2명으로 제한한다.
- 정보 전달용 단역은 가능하면 이름 없이 직책, 별칭, 기능으로 처리한다.
- 조직 구성원은 개인명보다 조직/직책/코드명으로 먼저 처리한다.

### 초과 가능 조건

다음 조건을 모두 만족할 때만 active 핵심 인물 상한을 넘을 수 있다.

1. 기존 인물로 기능을 대체할 수 없다.
2. 최소 3회 이상 재등장 계획이 있다.
3. 주인공의 선택, 갈등, 보상, 복선 중 하나를 직접 바꾼다.
4. `cast_registry.json`에 역할, 첫 등장, 상태, 재등장 목적을 기록한다.
5. 사용자 요청 범위 안에서만 추가한다.

## 새 인물 생성 게이트

새 named character를 만들기 전 아래 질문에 답합니다.

- [ ] 이 인물의 기능을 기존 인물이 대신할 수 없는가?
- [ ] 이 인물이 최소 3회 이상 재등장할 예정인가?
- [ ] 이 인물이 주인공의 선택을 바꾸는가?
- [ ] 이 인물이 복선, 갈등, 독자 보상 중 하나를 담당하는가?
- [ ] 이름 없는 직책/조직/단역으로 처리하면 안 되는가?
- [ ] 기존 조연 또는 빌런의 목적을 흐리게 만들지 않는가?

세 문항 이상 “아니오”라면 새 named character를 만들지 않습니다.

## 인물 상태값

`cast_registry.json`의 status는 다음 값을 우선 사용합니다.

- `active`: 현재 arc에서 반복 등장하거나 직접 영향을 준다.
- `supporting`: 조연으로 기능하지만 arc 핵심축은 아니다.
- `recurring_threat`: 반복 압박을 주는 추적자/빌런/조직원이다.
- `dormant`: 당장은 퇴장했지만 재등장 가능성이 있다.
- `one_off`: 단발 기능으로 끝난다. 이름 부여를 재검토한다.
- `merged`: 다른 인물에게 기능을 합쳤다.
- `dead_or_removed`: 서사에서 제거되었다.

## 역할 중복 점검

새 인물 또는 조연 강화 전 다음 중복을 확인합니다.

- 정보 제공자 중복
- 물리적 추적자 중복
- 조직 설명 담당 중복
- 주인공을 훈련시키는 조력자 중복
- 비슷한 말투/성격/직업의 조연 중복
- 독자 보상 없이 이름만 늘어나는 단역 중복

중복이 있으면 새 인물을 만들지 말고 기존 인물에게 역할을 병합합니다.

## 배치 후 cast 정리

3화 배치 완료 후 반드시 확인합니다.

- [ ] 새 named character 수를 기록했다.
- [ ] 신규 인물의 재등장 목적을 기록했다.
- [ ] active / dormant / one_off / merged 상태를 갱신했다.
- [ ] 기존 인물의 목적과 말투가 흔들리지 않았는지 확인했다.
- [ ] 다음 배치에서 사용하지 않을 인물을 정리 후보로 표시했다.

## final 저장 금지 조건

다음 중 하나라도 있으면 final 저장 전 review 또는 recovery_plan을 작성합니다.

- 신규 named character가 사용자 요청 범위를 넘어 추가되었다.
- 새 인물이 기존 인물 기능과 명백히 중복된다.
- 조연/빌런의 목적이 근거 없이 바뀌었다.
- active cast가 과도해져 회차 갈등의 초점이 흐려졌다.
- cast_registry 업데이트 없이 새 인물이 final에 등장한다.

## 보고 항목

회차 또는 배치 작업 후 보고에 다음을 포함합니다.

- 신규 named character 수
- active cast 수
- 병합/삭제/보류한 인물
- 다음 배치에서 정리할 인물
- cast_registry 업데이트 여부
